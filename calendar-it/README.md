# Calendar-It

צילום מסך של אירוע  → שיתוף לתיקייה ב-Drive → אירוע ביומן. אוטומטי.

**כתובת האפליקציה:** https://calendar-it.shahaf579.workers.dev
**קוד גישה לדשבורד:** `SohBeV0S-Zw2` (נשמר בעוגייה אחרי כניסה ראשונה, אפשר גם `?key=...` בכתובת)

הכל כבר פרוס (Worker + KV + cron כל 5 דקות). נשארו 2 צעדים חד-פעמיים כדי שהחיבור ל-Google יעבוד.

## שלב 1 — יצירת OAuth Client ב-Google Cloud Console

1. כנסו ל-https://console.cloud.google.com/ (עם shahaf579@gmail.com), ואם אין כבר פרויקט — צרו פרויקט חדש (למשל "calendar-it").
2. **APIs & Services → Library**: הפעילו את **Google Drive API** ואת **Google Calendar API**.
3. **APIs & Services → OAuth consent screen**:
   - User Type: **External**.
   - מלאו שם אפליקציה + מייל תמיכה (המייל שלכם).
   - ב-Scopes אין צורך להוסיף כלום ידנית.
   - ב-Test users: הוסיפו את shahaf579@gmail.com.
   - שמרו — האפליקציה תישאר במצב "Testing", וזה בסדר גמור לשימוש אישי (אין צורך באימות של Google).
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID**:
   - Application type: **Web application**.
   - Authorized redirect URIs: הוסיפו בדיוק
     ```
     https://calendar-it.shahaf579.workers.dev/auth/callback
     ```
   - צרו, והעתיקו את ה-**Client ID** וה-**Client Secret**.

## שלב 2 — הזנת המפתחות ל-Worker

בתיקייה `calendar-it/` (יש כבר `wrangler.toml` מוכן), הריצו:

```bash
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
```

(יבקש להדביק את הערך בכל פעם — זה ה-Client ID / Secret שהעתקתם למעלה.)

## שלב 3 — יצירת תיקיית Drive וחיבור

1. ב-Google Drive שלכם (shahaf579@gmail.com), צרו תיקייה חדשה **בתיקיית הבסיס** בשם בדיוק:
   ```
   CalendarIt
   ```
   (אפשר לשנות את השם ב-`DRIVE_FOLDER_NAME` ב-`wrangler.toml` אם רוצים שם אחר — האפליקציה רק קוראת מהתיקייה, אף פעם לא יוצרת אותה בעצמה, כדי לא לדרוש הרשאת כתיבה רחבה על כל ה-Drive.)
2. גשו ל-https://calendar-it.shahaf579.workers.dev/ , הכניסו את קוד הגישה, ולחצו **"התחבר עם Google"**. תעברו למסך הרשאות של Google — אשרו גישה ל-Drive וליומן.
3. חוזרים לדשבורד — אמורים לראות "✅ מחובר" ו-"✅ נמצאה תיקייה".

> **התחברתם כבר לפני 2026-08-24?** ההרשאה ל-Drive שודרגה מ"קריאה בלבד" ל-"קריאה+כתיבה" (כדי לאפשר מחיקת תמונות ורישום לוג, ראו למטה) — צריך ללחוץ **"התחבר עם Google" שוב** כדי לאשר את ההרשאה המורחבת, אחרת מחיקת התמונות וקובץ הלוג פשוט ייכשלו בשקט (האירוע עדיין ייכנס ליומן/ICS כרגיל).

## איך זה עובד ביום-יום

- גוללים, רואים אירוע, **צילום מסך**.
- **שיתוף → Drive → שמירה בתיקיית "CalendarIt"** (share sheet רגיל בטלפון).
- **אוטומטי לגמרי, כל 5 דקות** — יש cron trigger שרץ ברקע (`*/5 * * * *`), אין צורך ללחוץ שום כפתור. כפתור "סנכרן עכשיו" בדשבורד הוא רק לבדיקה מיידית, בלי לחכות לטיק הבא.
- ה-Worker קולט את הקובץ, שולח אותו למודל ראייה (Workers AI) שקורא את הטקסט (תאריך בפורמט יום.חודש, שעה, שם, מקום), ומכניס את זה כאירוע ישירות ליומן Google הראשי שלכם.
- **אם החילוץ הצליח** (יש תאריך): נוצר קובץ ICS גיבוי, האירוע מוזן ליומן, **התמונה המקורית עוברת לפח (trash) ב-Drive** (לא נמחקת לצמיתות — ניתנת לשחזור כ-30 יום), ונוספת שורה ל-`calendar-it-log.txt`.
- **אם משהו לא ברור** (לדוגמה לא נמצא תאריך בתמונה, או שהמודל החזיר טקסט שלא הצליח להיפרס כ-JSON) — האירוע לא יתווסף אוטומטית, קובץ ICS לא נוצר, **התמונה נשארת בתיקייה** (כדי שאפשר יהיה לבדוק אותה ידנית), ונוספת שורה מפורטת (כולל הפלט הגולמי מה-AI) ל-`calendar-it-errors.txt`.

## שני קבצי לוג ב-Drive (באותה תיקייה)

- **`calendar-it-log.txt`** — כל אירוע שנכנס/נמחק מהיומן: תאריך ושעה שהעיבוד רץ, מה זוהה (שם/תאריך/מקום), האם נוסף ליומן, ואם התמונה נמחקה (הועברה לפח) או נשארה. מחיקה ידנית מהדשבורד (ראו למטה) גם מתעדכנת כאן.
- **`calendar-it-errors.txt`** — כל מקרה שה-AI לא הצליח לחלץ ממנו אירוע: קוד השגיאה, קישור לתמונה המקורית (שעדיין נמצאת בתיקייה), **והפלט הגולמי שהמודל החזיר** — כדי שאפשר יהיה להבין מה השתבש בלי לפתוח שוב את התמונה.

שני הקבצים נכתבים מחדש בכל סנכרון שמעבד לפחות תמונה אחת (לא append) מתוך רשימת 100 האירועים האחרונים בדשבורד — תמיד תואמים למה שרואים ב-https://calendar-it.shahaf579.workers.dev/. יש קישורים אליהם ישירות מהדשבורד ("📋 לוג אירועים" / "⚠️ לוג כשלונות").

## מחיקת אירוע מהיומן, מהדשבורד

לכל אירוע שנוסף בהצלחה יש כפתור **"🗑️ מחק מהיומן"** — מבקש אישור, ואז מוחק את האירוע מ-Google Calendar (ה-API של Calendar, לא נוגע בתמונה ב-Drive). הכרטיסייה מתעדכנת לסטטוס "נמחק מהיומן", וגם קובץ `calendar-it-log.txt` מתעדכן בהתאם.

## סינון בדשבורד

מעל רשימת האירועים יש שלושה כפתורי סינון: **הכל** / **השבוע האחרון** / **דורש בדיקה** — סינון מיידי בצד הלקוח, בלי טעינה מחדש. יש גם שורת סיכום קבועה "X נוספו בשבוע האחרון".

## מגבלות ידועות (v1)

- תמונות מעל 4MB לא נשלחות למודל הראייה (כדי לא לחרוג ממגבלות הבקשה) — יסומנו כ"דורש בדיקה ידנית", התמונה נשארת בתיקייה.
- אין עריכה ידנית של פרטי אירוע בדשבורד — רק תצוגה + קובץ ICS + מחיקה. אם החילוץ טעה (למשל שם או מקום שגוי), פותחים את קובץ ה-ICS ומתקנים ביד באפליקציית היומן, או עורכים ישירות ביומן אחרי שנוסף (שימו לב: התמונה המקורית כבר תהיה בפח אם ההוספה ליומן/ICS הצליחה, גם אם הפרטים לא מדויקים).
- ברירת המחדל למשך אירוע היא שעתיים (רוב הפוסטים לא מציינים שעת סיום).
- מחיקת התמונה היא "העברה לפח" (trash), לא מחיקה קבועה — תגידו אם תרצו שזו תהיה מחיקה סופית מיידית במקום.
- מחיקת אירוע מהיומן היא **סופית** (ה-API של Calendar לא מציע "פח" כמו Drive) — אם התמונה המקורית כבר נמחקה גם היא, אין דרך לשחזר את האירוע חוץ מלצלם מסך שוב.
